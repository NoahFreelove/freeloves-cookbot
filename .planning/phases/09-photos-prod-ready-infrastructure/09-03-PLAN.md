<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Recipe.PhotoUrl (DB) → browser <img src> | Stored URL crosses out to browser as a src attribute |
| RecipeDocument.PhotoUrl (canonical JSON) → AiChat <img> | Same path via canonical accumulator |
| External photo host → browser | The photo bytes themselves never touch CookBot in this plan; browser fetches direct |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-03-01 | Information Disclosure | Referer header leaks recipe URL to external photo host | mitigate | Every <img> in this plan sets referrerpolicy="no-referrer". |
| T-09-03-02 | Denial of Service | Infinite onerror loop when PhotoUrl is broken | mitigate | Blazor state flag (per-surface scope: _heroPhotoFailed, _photoFailedFor HashSet, _aiChatPhotoFailed). After first failure the placeholder/nothing renders, the browser cannot re-fetch. |
| T-09-03-03 | Tampering | XSS via malicious PhotoUrl reaching <img src> | mitigate | RecipePhotoUrlValidator (Plan 09-01) was the gate at write time; entity PhotoUrl rows can only have been written through that validator. AI-emitted PhotoUrl runs through the same validator in Plan 09-05's AnthropicAiService return path. |
| T-09-03-04 | Information Disclosure | AI canvas shows a previously-generated PhotoUrl after conversation switch | accept | _aiChatPhotoFailed is per-render; switching conversations resets _lastStructuredRecipe which resets the whole render. Edge case is brief flash on stale frame; not a real disclosure (single-user trusted-LAN). |
</threat_model>
