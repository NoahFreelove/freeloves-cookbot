<objective>
Build the Cooklang `.cook` projector as a pure `CookBot.Application` function over the canonical v4 `RecipeDocument`. This plan delivers only the pure transform + its golden-file/sanitization tests — the RecipeView export button and download wiring are Plan 03.

Purpose: INTEROP-03/INTEROP-04 require a one-way Cooklang text export. Cooklang has no escape character, single-token names terminate at any punctuation, and recipe-level equipment has no idiomatic inline token — so the emission rules are subtle and benefit from being isolated and snapshot-locked before any UI wiring.

Output: `CooklangRecipeProjector.cs`, unit + Verify snapshot tests, and the committed `.verified.txt` baseline.
</objective>

    Create `public static class CooklangRecipeProjector` in file-scoped `namespace CookBot.Application.Recipes;` with `public static string Project(RecipeDocument doc)` (D9 — pure, no DI, no data-service calls, no CanonicalDocumentJson access; StepNode is polymorphic so pattern-match, do not assume a flat shape). Build the output with a StringBuilder.

    Recipe-level metadata (D8): emit `>> servings: {Servings}` and, when present, `>> prep time: {PrepTimeMinutes} min` / `>> cook time: {CookTimeMinutes} min`. When Provenance has SourceName/AuthorName/SourceUrl, emit a `>> source: ...` metadata line. Recipe-level Equipment[] (D8): emit each as a `-- Equipment: {item}` comment line (or a single `>> equipment: a, b, c` line) — NEVER as inline `#cookware` (inline # is reserved for step-scoped cookware).

    Steps (pattern-match doc.Steps):
    - SectionStep s → emit `== {s.Heading} ==` on its own line (D8 / SC2).
    - ContentStep c → emit the step prose: take `RecipeStepTextFormatter.ToPlainText(c.Text)` (reuse, D10 — strips [name](#id) to its label) then SANITIZE literal `@`, `#`, `~` out of the resulting prose before emission (D7 — Cooklang has NO escape char; strip or replace, do NOT backslash-escape). Then append, after the step:
      - timers from c.Timers → `~{Duration%Unit}` for each, or `~Label{Duration%Unit}` when Label is non-empty (D7 — always braces form).
      - c.Temperature → `-- {Value}{unit-symbol}` comment (map TemperatureUnit F/C/Gas to °F/°C/"Gas Mark").
      - c.DonenessCue → `-- {DonenessCue}` comment.

    Substitutions (Warning-2 resolution — substitutions live ONLY on IngredientEntry.Substitutions; there is NO per-step substitution model): after all steps and after the ingredients section, emit a single TRAILING comment block at the END of the .cook output. For each IngredientEntry that has Substitutions, emit one line per substitution: `-- Substitution ({ingredient name}): {sub.Note}`. Iterate doc.Ingredients in order, then each ingredient's Substitutions in order, so the block is deterministic and pinnable in the golden snapshot. Do NOT scatter substitution comments inline among the steps and do NOT hedge about "per-step subs" — there are none.

    Ingredients section: emit each IngredientEntry as the ALWAYS-braces token `@{Name}{{FractionFormatter.Format(Amount)}%{Unit}}` — i.e. `@name{amount%unit}` (D7/SC2/§Pitfall 3). When Unit is empty emit `@name{amount}`; when both amount and unit are absent emit `@name{}`. Never emit a bare `@name` (single-token names terminate at punctuation/whitespace and would corrupt multi-word names).

    Do NOT parse step text for ingredients — ingredient tokens come from doc.Ingredients only (§Anti-Patterns). The output is one-way export; no re-import affordance.

    Output ORDER (deterministic, pinned by the golden snapshot): metadata (>> lines) → equipment lines → steps (sections + content + per-step timers/temp/doneness comments) → ingredients section → trailing Substitution comment block.
