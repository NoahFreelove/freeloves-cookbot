<objective>
Wire the Wave-1 `RecipeUnitDisplayService` (Plan 11-01) into the three consumer surfaces so ingredient amounts and per-step temperatures DISPLAY in the user's `UserProfile.UnitSystem` by default, with a per-recipe localStorage toggle back to the AI-emitted original units. This is the WIRING half of CLEANUP-04 — all conversion math already exists and is tested in 11-01; this plan only threads it through the render paths and adds the toggle.

Two pattern-map traps to honor:
1. RecipeView + AiChat render canonical `IngredientEntry` / `ContentStep` (temperature reachable directly). CookingMode renders EF entities (`RecipeIngredient` / `RecipeStep`) that carry NO temperature field — converting step temps there needs an extra `Recipe.CanonicalDocumentJson` canonical-first read.
2. Toggle persistence mirrors the QOL-05 accent-picker localStorage pattern (read-in-OnAfterRender, write-on-toggle, prerender-safe try/catch), keyed by recipe id, default = converted.

Output: converted display on all three surfaces + a per-recipe toggle. Canonical doc untouched.
</objective>
