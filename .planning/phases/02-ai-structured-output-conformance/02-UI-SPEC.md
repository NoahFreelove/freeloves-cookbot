## Surface Inventory — New Phase 2 Surfaces

### Surface 1: "Drafting recipe…" In-Flight Indicator

**Where:** `AiChat.razor` — replaces the current streaming `MudProgressLinear` that appears inside the chat bubble during `_isStreaming`.

**What it is:** A chat bubble in the assistant position (left-aligned, `background: #FFF3E0`) containing:
1. `MudText Typo="Typo.body2" Color="Color.Secondary"` — text: "Drafting recipe…"
2. `MudProgressLinear Indeterminate="true" Color="Color.Primary" Size="Size.Small"` directly below the text

**Behavior:**
- Appears when `_isDraftingRecipe` (new bool state, separate from general `_isStreaming`) is true
- Covers the entire span: initial call + up to 2 repair retries — the user never sees a retry counter
- Disappears when `IAiRecipeGenerator` returns (success or final failure)
- The existing `_isStreaming` bubble for free-form (non-recipe) turns stays unchanged

**Component spec:**
```razor
<div class="d-flex justify-start mb-3">
    <MudPaper Class="pa-3" Elevation="1"
              Style="max-width: 80%; border-radius: 12px; background: #FFF3E0;">
        <MudText Typo="Typo.body2" Color="Color.Secondary">Drafting recipe…</MudText>
        <MudProgressLinear Indeterminate="true" Color="Color.Primary" Size="Size.Small" Class="mt-2" />
    </MudPaper>
</div>
```

Source: CONTEXT.md D-01, D-07; discussion log "Compose-then-reveal" decision.

### Surface 2: "Save Recipe to Cookbook" Button — Gated on Structured Output

**Where:** `AiChat.razor` — replaces the current `HasRecipe(msg.Content)` check that drives the existing Save button.

**What it is:** `MudButton Variant="Variant.Outlined" Color="Color.Primary" Size="Size.Small"` — identical appearance to current, but visibility logic changes.

**Visibility rule:** Button renders only when the assistant turn was produced by `IAiRecipeGenerator` (a `StructuredResult<RecipeDocument>` with `Ok=true`). Free-form chat turns never show the button. Old turns that predate Phase 2 never show the button (CONTEXT.md D-24, D-25).

**Label:** "Save Recipe to Cookbook" — no change from today.

**Icon:** `Icons.Material.Filled.Save` — no change.

**Position:** Inside the assistant chat bubble, below the rendered recipe content — no change from today.

Source: CONTEXT.md D-24; `AiChat.razor` lines 168–172.

### Surface 3: "Edit and Save Anyway" Affordance

**Trigger:** `IAiRecipeGenerator` exhausts 2 repair retries without producing a valid `RecipeDocument`.

**Primary path (parser extracts something coherent — D-08):**

`AiChat.razor` transitions from the "Drafting recipe…" bubble to an error state bubble, then navigates to `RecipeEditor.razor` with best-effort fields pre-populated via query parameters or state.

**The error state chat bubble (shown before navigation):**

```razor
<MudPaper Class="pa-3" Elevation="1"
          Style="max-width: 80%; border-radius: 12px; background: #FFF3E0;">
    <MudAlert Severity="Severity.Warning" Dense="true" Class="mb-2">
        The AI could not produce a valid recipe after 2 attempts.
        You can edit the draft below and save it manually.
    </MudAlert>
    <MudStack Row="true" Spacing="1" Class="mt-2">
        <MudButton Variant="Variant.Outlined" Color="Color.Warning" Size="Size.Small"
                   StartIcon="@Icons.Material.Filled.Edit"
                   OnClick="OpenDraftInEditor">
            Edit and save anyway
        </MudButton>
        <MudButton Variant="Variant.Text" Color="Color.Primary" Size="Size.Small"
                   OnClick="RetryAiRequest">
            Try again
        </MudButton>
    </MudStack>
</MudPaper>
```

**RecipeEditor.razor inline validation banner (shown at top of editor when opened from failed AI draft):**

A `MudAlert Severity="Severity.Warning"` at the top of the editor page, before the recipe name field. It lists the unresolved validation errors from `RecipeValidator`. Copy:

- Heading: "Draft from AI — {N} field(s) need review"
- Body: bulleted list of `ValidationError.Path: ValidationError.Message` entries, one per line
- The alert uses `Dense="false"` so the full error list is readable
- The alert dismisses when the user corrects the last validation error and re-validates (or can be manually dismissed via a close icon)

**Fallback path (parser cannot extract anything — D-09):**

When `IRecipeFormatParser` returns null/empty from the raw AI response, the error state bubble instead shows:

```razor
<MudAlert Severity="Severity.Warning" Dense="true" Class="mb-2">
    The AI response could not be parsed. You can paste or retype it manually.
</MudAlert>
<MudStack Row="true" Spacing="1" Class="mt-2">
    <MudButton Variant="Variant.Outlined" Color="Color.Warning" Size="Size.Small"
               StartIcon="@Icons.Material.Filled.ContentPaste"
               OnClick="OpenRawInPasteDialog">
        Paste and fix manually
    </MudButton>
    <MudButton Variant="Variant.Text" Color="Color.Primary" Size="Size.Small"
               OnClick="RetryAiRequest">
        Try again
    </MudButton>
</MudStack>
```

`PasteRawTextDialog.razor` is opened pre-filled with the raw AI response string.

**Button styling rationale:** `Color.Warning` for the primary recovery action distinguishes it visually from `Color.Primary` normal-save paths. This signals "non-standard path" without using `Color.Error` (which implies unrecoverable failure).

Source: CONTEXT.md D-08, D-09; discussion log "Open chip editor pre-filled best-effort".

### Surface 4: Sanitized AI Error Surface

**Where:** `AiChat.razor` snackbar — `Snackbar.Add(sanitizedError, Severity.Error)`.

**What changes:** The UI currently binds `ex.Message` directly (see `AiChat.razor` line 352: `Snackbar.Add($"AI Error: {ex.Message}", Severity.Error)`). After Phase 2, all AI error paths return `StructuredResult<T>.SanitizedError` or `SendMessageResult.SanitizedError`; the `catch` block in `AiChat.razor` never receives a raw exception from AI calls — it receives a pre-sanitized string.

**Snackbar copy pattern (prescriptive):**

| Scenario | Snackbar copy | Severity | Action |
|----------|--------------|----------|--------|
| Invalid API key / 401 | "Could not connect to the AI — check your API key in Profile settings." | `Severity.Error` | `MudSnackbarAction` label "Open settings" → navigates to `/profile` |
| Network error / timeout | "Could not reach the AI. Check your internet connection and try again." | `Severity.Error` | Dismiss only (default MudBlazor snackbar close) |
| Repair budget exhausted | (Not a snackbar — see Surface 3 chat bubble above) | — | — |
| Unknown AI error | "Something went wrong with the AI. Please try again." | `Severity.Error` | Dismiss only |

**Key constraint:** The `SanitizedError` string returned by `SecretRedactor` is never bound directly to snackbar copy in user-visible form. `AiChat.razor` maps the sanitized error to one of the above copy templates based on the error category conveyed in `StructuredResult.SanitizedError` (a simple prefix or enum code, not the raw message). If no category can be inferred, use "Something went wrong with the AI. Please try again."

**What the snackbar must NEVER contain:**
- Any `sk-ant-*` substring
- Any API key fragment (even partial)
- Any `x-api-key` or `authorization` header name or value
- Raw exception stack traces or HTTP response bodies

Source: CONTEXT.md D-16, D-17, D-18; REQUIREMENTS.md AI-07; `AiChat.razor` line 352.

### Surface 5: Repair Loop Progress (Invisible)

**Decision:** The validate→repair→fail loop is completely transparent to the user. The "Drafting recipe…" indicator (Surface 1) covers the full span. No "Attempt 1 of 2" counter, no "Retrying…" state change.

Source: CONTEXT.md D-07 — "Repair loop is silent to the user during attempts."

---

### Surface 6: Legacy Conversation Resume — No UI Hint

**Decision:** When a conversation with `FormatVersion < 2` is loaded and the system note is prepended at request-assembly time, the user sees no UI indicator of the upgrade. The `FormatVersion = 2` stamp happens on the next save, silently. No banner, no chip, no toast.

Rationale: Trusted-LAN app with a single developer; the format upgrade is invisible infrastructure. A banner would add noise without user value.

Source: CONTEXT.md D-22, D-23.

---

### Surface 7: "Save Recipe" Button Absence on Old Turns

**Decision:** Assistant turns that predate Phase 2 (i.e., stored in `MessagesJson` from `AiConversation.FormatVersion < 2` conversations) do not show a "Save Recipe to Cookbook" button. If the user wants to extract a recipe from an old turn, they use "Paste Raw Text" manually. No affordance is added to guide them to this — it is an accepted edge case.

Source: CONTEXT.md D-25.

---

### Surface 8: Cookbook Import with Upcaster Errors (MIGRATION-04)

**Where:** `ImportCookbookDialog.razor` — existing dialog.

**What changes:** `CookbookTransferService.Deserialize` now runs per-recipe through the upcaster + validator. When N of M recipes have validation errors, the existing error surface is extended:

Current pattern:
```
Snackbar.Add(string.Join(" ", errors), Severity.Error);
```

New pattern when partial success (some recipes valid, some not):

```razor
<MudAlert Severity="Severity.Warning" Dense="false" Class="mt-2">
    {N} of {M} recipes had validation errors and were skipped.
    The rest were imported successfully.
</MudAlert>
```

This alert appears inside `ImportCookbookDialog` before the "Cancel" button, inline in the dialog body. The dialog does NOT close automatically — the user sees the count and confirms with an "Import anyway ({M - N} recipes)" button or "Cancel".

When ALL recipes fail validation:
```
Snackbar.Add("No recipes could be imported — the file may be corrupted or incompatible.", Severity.Error);
```
Dialog stays open; user can try a different file.

Source: CONTEXT.md D-19; REQUIREMENTS.md MIGRATION-04.

## Interaction Contracts

### AiChat.razor State Machine (recipe-emitting turns)

```
IDLE
  → user submits message with recipe intent
DRAFTING  (_isDraftingRecipe = true)
  → "Drafting recipe…" bubble visible
  → send button disabled
  → input field disabled
  → IAiRecipeGenerator called (internally: up to 3 model calls)
  → on Ok=true:
RECIPE_READY
  → recipe card rendered in assistant bubble (Markdig-rendered)
  → "Save Recipe to Cookbook" button visible
  → _isDraftingRecipe = false
  → on validation failure after max retries:
DRAFT_FAILED
  → "The AI could not produce a valid recipe…" alert bubble
  → "Edit and save anyway" + "Try again" buttons
  → _isDraftingRecipe = false
  → on transport/auth error:
ERROR
  → snackbar with sanitized copy (see Surface 4 table)
  → _isDraftingRecipe = false
```

Free-form (non-recipe) turns use the existing `_isStreaming` path unchanged.

### "Edit and save anyway" Navigation

1. User clicks "Edit and save anyway" in the `DRAFT_FAILED` bubble.
2. `AiChat.razor` calls `IRecipeFormatParser` on `StructuredResult.RawResponse` (parser-route, coercion-with-warnings).
3. If parser returns a usable shape: navigate to `RecipeEditor.razor` (new recipe, pre-populated fields) with the inline validation banner (Surface 3 primary path).
4. If parser returns null: open `PasteRawTextDialog.razor` pre-filled with the raw AI response string (Surface 3 fallback path).
5. Standard `RecipeValidator` gate applies on Save in `RecipeEditor.razor` — non-conforming recipes still cannot persist.

### Snackbar action for API key error

```razor
Snackbar.Add(
    "Could not connect to the AI — check your API key in Profile settings.",
    Severity.Error,
    config =>
    {
        config.Action = "Open settings";
        config.ActionColor = Color.Inherit;
        config.Onclick = _ => { Navigation.NavigateTo("/profile"); return Task.CompletedTask; };
    });
```
