## Accomplishments

- **AI-02 / AI-03 orchestrator landed.** `IAiRecipeGenerator.GenerateAsync` runs the validate→repair→fail state machine on top of `IStructuredAiService.SendStructuredAsync<RecipeDocument>`. `MaxRepairAttempts = 2` is a `const int` (D-05; not configurable). Up to 3 total model calls per generation request — verified by a unit test that asserts `fake.Calls.Count == 3` on full budget exhaustion.
- **Refusal + transport short-circuit verified.** When `IStructuredAiService` returns `Ok=false` with `Validation == null && SanitizedError != null`, the orchestrator returns immediately without consuming any retry budget. Two unit tests (`RefusalShortCircuit`, `TransportFailureShortCircuit`) each assert `fake.Calls.Count == 1`. This preserves token budget for paths that *can* converge.
- **Minimal repair prompt verified.** The repair turn carries exactly two messages — `[user: original prompt, user: validator-error feedback]`. No assistant turn, no full conversation history. The `RepairConvergesOnAttempt1` test asserts `repairCall.Messages.Count == 2` AND `Assert.All(... m.Role == "user")` AND that the repair-feedback content contains the validator's `/name` path string and the literal "did not match the required schema" string.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 — Bug] DI lifetime mismatch: Singleton orchestrator + Scoped IStructuredAiService**
- **Found during:** Task 4 (running `dotnet ef migrations add` triggered design-time DI validation)
- **Issue:** The plan specified `services.AddSingleton<IAiRecipeGenerator, AiRecipeGenerator>()` ("orchestrator is stateless"). But `IStructuredAiService` is registered Scoped (Plan 02: same instance as `IAiService`). `Microsoft.Extensions.DependencyInjection`'s `ServiceProviderOptions.ValidateScopes` (default-on for `Microsoft.Extensions.Hosting`) rejects this combination at design time: `Cannot consume scoped service 'IStructuredAiService' from singleton 'IAiRecipeGenerator'`.
- **Fix:** Changed registration to `AddScoped<IAiRecipeGenerator, AiRecipeGenerator>()`. The orchestrator IS still stateless — Scoped is the correct lifetime to inherit from its dependencies, and per-request scope is the natural unit anyway.
- **Files modified:** `src/CookBot.Application/DependencyInjection.cs`
- **Commit:** 95b4c69 (folded into Task 4 because the migration tooling surfaced the issue)

**2. [Rule 3 — Blocking dependency] First ILogger usage in src/ requires Microsoft.Extensions.Logging.Abstractions**
- **Found during:** Task 3 (writing AiRecipeGenerator)
- **Issue:** `CookBot.Application` had `Microsoft.Extensions.DependencyInjection.Abstractions 10.0.3` but not `Microsoft.Extensions.Logging.Abstractions`. The plan explicitly anticipates this ("this is the FIRST use of ILogger in src/") but the package addition is functionally a deviation from the plan's "no new packages" verification check.
- **Fix:** Added `<PackageReference Include="Microsoft.Extensions.Logging.Abstractions" Version="10.0.3" />` to `CookBot.Application.csproj`. Same major version as the existing DI Abstractions; foundational Microsoft.Extensions.* abstraction package; not on any forbidden list (no `Microsoft.Extensions.AI`, no `Newtonsoft`, no `NJsonSchema`, no `Anthropic` SDK).
- **Files modified:** `src/CookBot.Application/CookBot.Application.csproj`
- **Commit:** 061ff3d (folded into Task 3 RED commit because the test file referenced `NullLogger<AiRecipeGenerator>.Instance` which requires the abstractions package)

**3. [Rule 1 — Test fixture mismatch] ValidationResult / ValidationError signatures in plan-text don't match codebase**
- **Found during:** Task 3 (writing AiRecipeGeneratorTests)
- **Issue:** Plan text used `ValidationResult(IsValid: false, Errors: ..., Warnings: ...)` and `ValidationError("name", "name must not be empty", ValidationSeverity.Error)`. Actual codebase records (Phase 1) are `ValidationResult(Errors, Warnings)` with `IsValid` computed, and `ValidationError(Path, Code, Message)` — no `ValidationSeverity` enum exists.
- **Fix:** Test fixtures use the actual signatures. The repair-prompt assertion (`Assert.Contains("/name", repairCall.Messages[1].Content)`) accommodates the JSON-pointer-style path the validator actually emits (e.g. `/name`, not `name`).
- **Files modified:** `tests/CookBot.Tests/AI/AiRecipeGeneratorTests.cs`
- **Commit:** 061ff3d

**4. [Rule 1 — Migration auto-generation] defaultValue: 0 → defaultValue: 1**
- **Found during:** Task 4 (inspecting auto-generated migration)
- **Issue:** EF Core's auto-generation emitted `defaultValue: 0` because the entity-side default of `2` doesn't translate to a DB-side default for back-fill of existing rows. Per D-22, existing rows must back-fill to `1` (legacy YAML wire), not `0` or `2`.
- **Fix:** Edited the `Up()` body's `defaultValue: 0` → `defaultValue: 1`. This is the one allowed manual edit per the plan's `<deviations>` block. Added a code comment documenting the why.
- **Files modified:** `src/CookBot.Infrastructure/Migrations/20260426053934_AiConversationFormatVersion.cs`
- **Commit:** 95b4c69
