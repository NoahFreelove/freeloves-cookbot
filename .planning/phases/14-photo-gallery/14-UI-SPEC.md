## Spacing Scale

All values are drawn from existing tokens in `cookbot-design.css`. No new values are introduced.

| Token | Value | CSS variable / source | Usage in Phase 14 |
|-------|-------|-----------------------|-------------------|
| xs | 4px | hardcoded | Gap between thumbnail strip items |
| sm | 8px | hardcoded | Inline icon gap within photo-card action buttons; gap on photo-card button row; vertical padding on icon-only buttons; gap + vertical padding on the "Add photos" upload label; margin-top on upload progress status line |
| md | 16px | `--gap` / `--pad-sm` (`cookbot-design.css:49`) | Gap between photo cards in editor grid; caption input margin; photo card padding |
| lg | 24px | `--pad` (`cookbot-design.css:48`) | Section-level padding within RecipeView gallery block |
| xl | 32px | hardcoded | Vertical space between hero + thumbnail strip |

Compact density (`[data-density="compact"]`): all compact-density overrides (`--pad`, `--pad-sm`, `--gap`) are inherited automatically from `cookbot-design.css` — the gallery surfaces carry the `data-density` attribute via the page shell and need no re-declaration here.

**Exceptions:**
- Hero image height: 420px (fixed, matches existing RecipeView hero — `RecipeView.razor:145`)
- Thumbnail height: 72px with auto width (maintains aspect ratio, does not bust grid rhythm)
- Photo card thumbnail in editor: 120px × 90px (4:3, matches existing `RecipePhotoComposite` 240×180 at 50% scale)
- Min touch target for reorder/delete buttons: `min-height: 36px` declared explicitly on each icon-only reorder/delete button (not derived from padding math). Buttons use `padding: 8px` to align to the 8-point grid; the `min-height: 36px` guarantee is separate and explicit.

## Color

All values are existing CSS custom properties from `cookbot-design.css`. No new color tokens.

| Role | Value / Token | Usage |
|------|---------------|-------|
| Dominant surface (60%) | `--cream` (`#FBF6E7`) | Page background, gallery section background |
| Secondary surfaces (30%) | `--paper` (`#FFFFFF`) / `--paper-2` (`#FCFAF3`) | Photo cards in editor (`.cb-card`), thumbnail strip container |
| Accent (10%) | `--accent` (`#C2410C`) | Hero-badge indicator only: the "Hero" state label on the set-primary button; the 2px focus ring on all interactive elements |
| Destructive | `--warn` (`#B45309`) / `--warn-soft` (`#FBEACE`) | Delete-photo confirmation text and alert role; URL validation error messages (matches existing `RecipePhotoComposite.razor:70`) |

**Accent reserved for:**
1. The "Set as hero" button when `IsPrimary = true` — renders with `cb-btn accent` variant to communicate the active primary state
2. Focus rings on all interactive elements (2px solid `var(--accent)` — existing A11Y standard from v1.2)
3. The "Suggest photo search terms" AI button — uses `cb-btn accent` to distinguish it from ghost add/delete actions, matching the AI button treatment in existing RecipeEditor AI prompts

**All other buttons** use `cb-btn ghost` (reorder, delete, add-photo, paste-URL).

**Disabled state:** `opacity: 0.4` + `cursor: not-allowed` — matches existing disabled pattern on `CbButton.razor` (`disabled="@Disabled"` attribute).

**Photo card border:** `1px solid var(--line)` (`rgba(60, 42, 18, 0.10)`) — matches `.cb-card` in `cookbot-design.css:137`.

**Thumbnail hover ring:** `2px solid var(--line-strong)` on hover (`cookbot-design.css:18` — `rgba(60, 42, 18, 0.18)`; token confirmed present); `2px solid var(--accent)` when that photo is the currently displayed hero in RecipeView.

## Surface 1: RecipeView Gallery (Display)

### Layout

```
┌─────────────────────────────────────────────────────┐
│  [hero image 100% width, 420px height, object-fit:  │
│   cover, border-radius: 10px]                        │
│  — or — <StripedPlaceholder Width="100%" Height="420"│
│           Label="hero photo · 4:3" />                │
├─────────────────────────────────────────────────────┤
│ [thumb] [thumb] [thumb] [thumb] ... (scroll if >N)  │
│ 72px h, gap 4px, margin-top: 8px                    │
└─────────────────────────────────────────────────────┘
```

### Hero block (UNCHANGED from existing code)

- Render the primary `RecipePhoto` (the one with `IsPrimary = true`) using the **identical** markup pattern from `RecipeView.razor:138-150`:
  - `referrerpolicy="no-referrer"`
  - `loading="lazy"`
  - `@onerror` — one-shot flag per photo ID; on error replace that photo's slot with `StripedPlaceholder`
  - `style="width:100%;height:420px;object-fit:cover;border-radius:10px;display:block;"`
  - `alt="@($"{_doc.Name} hero photo")"`
- When `_photos` is empty or all photos have errored: `<StripedPlaceholder Width="100%" Height="420" Label="hero photo · 4:3" />`
- Source: `CONTEXT.md §specifics` + `RecipeView.razor:133-150` (verified match)

### Thumbnail strip

- Renders only when `_photos.Count > 1` (single-photo recipes show only the hero, no strip)
- `display: flex; flex-wrap: wrap; gap: 4px; margin-top: 8px;`
- Each thumbnail:
  - `height: 72px; width: auto; aspect-ratio: 4/3; object-fit: cover; border-radius: 6px; cursor: pointer;`
  - Same hardening as hero: `referrerpolicy="no-referrer"`, `loading="lazy"`, `@onerror` one-shot per photo ID
  - `alt="@($"{_doc.Name} photo {idx + 1}")"` — sequential counter, not empty
  - Active state (currently displayed hero): `outline: 2px solid var(--accent); outline-offset: 2px;`
  - Hover state: `outline: 2px solid var(--line-strong); outline-offset: 2px;` (token confirmed at `cookbot-design.css:18`)
  - Click: swaps the hero view (`_displayedPhotoId = photo.Id`) — **ephemeral, client-side only** — does not call any service or change `IsPrimary`
  - Keyboard: `tabindex="0"`, responds to `Enter` and `Space` via `@onkeydown`
  - ARIA: `role="button"` + `aria-label="View @(_doc.Name) photo @(idx + 1)"` + `aria-pressed="@(photo.Id == _displayedPhotoId)"`

### Caption

- If `photo.Caption` is non-empty: render it as a single line below the hero, `font-size: 14px; color: var(--ink-3); margin-top: 4px; font-style: italic;` — matches the ingredient note rendering style from `RecipeView.razor:192`
- If null/empty: render nothing (no empty caption placeholder in view mode)

## Surface 2: RecipeEditor Multi-Photo Manager (Authoring)

### Layout overview

The multi-photo manager replaces `RecipePhotoComposite.razor` at the top of the editor. It is a new component `RecipePhotoGalleryManager.razor` placed in `RecipeEditorParts/`.

```
┌─────────────────────── cb-card ──────────────────────────┐
│ CbEyebrow: Photos                    [photo count chip]  │
├──────────────────────────────────────────────────────────┤
│  ┌──────────────────────────────────────────────────┐    │
│  │ [photo-card] [photo-card] [photo-card] ...        │    │
│  │ (flex-wrap row, gap: 16px)                        │    │
│  └──────────────────────────────────────────────────┘    │
├──────────────────────────────────────────────────────────┤
│  [Add photos button / file input]  [Paste URL input]     │
│  [AI search-term button — gated]                         │
│  ─────────────────────────────────────────────────────   │
│  Copyright disclaimer line (always visible)              │
└──────────────────────────────────────────────────────────┘
```

### Photo card (per photo in the gallery)

Each photo card is a `<div class="cb-card">` with `padding: 16px; display: flex; flex-direction: column; gap: 8px; width: 180px;`. Cards wrap in a flex row (`flex-wrap: wrap; gap: 16px`).

```
┌──── cb-card 180px ────┐
│ [img 120×90 or ph]    │
│ [caption input]       │
│ [↑] [↓] [Hero] [🗑]  │
└───────────────────────┘
```

**Thumbnail inside card:**
- `width: 120px; height: 90px; object-fit: cover; border-radius: 6px; display: block;`
- Same hardening: `referrerpolicy="no-referrer"`, `loading="lazy"`, `@onerror` one-shot
- Hero photo card gets `outline: 2px solid var(--accent); outline-offset: 2px;` border
- `alt="Photo @(idx + 1)"`

**Caption input:**
- `<CbInput>` component, `Type="text"`, `Placeholder="Caption (optional)"`, `MaxLength="512"`
- Bound to `photo.Caption`; updates fire `RecipePhotoService.UpdateCaptionAsync` immediately (no batch with recipe save — same immediate-persist pattern as other gallery mutations per RESEARCH.md §Open Questions)
- `aria-label="Caption for photo @(idx + 1)"`

**Reorder and management buttons (bottom row of card):**
- Container: `display: flex; gap: 8px; align-items: center;`
- All buttons use `<CbButton Variant="Ghost">` with icon-only content at `padding: 8px` and explicit `min-height: 36px; min-width: 36px;` to guarantee the 36px touch target independent of padding math
- Move-up: `<Icon Name="@Icon.Names.ArrowL" Size="14" />` (rotated 90° via `style="transform:rotate(90deg)"`) — `aria-label="Move photo up"` — `disabled` when `idx == 0`
- Move-down: `<Icon Name="@Icon.Names.ArrowR" Size="14" />` (rotated 90°) — `aria-label="Move photo down"` — `disabled` when `idx == _photos.Count - 1`
- Set as hero: `<CbButton Variant="@(photo.IsPrimary ? CbButtonVariant.Accent : CbButtonVariant.Ghost)">` — label text: "Hero" when `IsPrimary`, "Set hero" when not — `disabled` when `photo.IsPrimary` — `aria-label="Set as hero photo"` — `aria-pressed="@photo.IsPrimary"`
- Delete: `<CbButton Variant="Ghost">` + `<Icon Name="@Icon.Names.Trash" Size="14" />` — `aria-label="Delete photo @(idx + 1)"` — triggers `CbConfirmDialog` before calling delete service

**Semantic note:** The "Set as hero" buttons across all cards form a logical radio group. Render them inside `<div role="radiogroup" aria-label="Hero photo selection">` wrapping all photo cards, with each "Set hero" button having `role="radio"` and `aria-checked="@photo.IsPrimary"`. This satisfies the A11Y carry-forward requirement for exactly-one-primary expressed semantically as a radio group.

### Add photos affordance

- Placed below the photo card grid
- Upload button: `<label class="cb-btn ghost" style="cursor:pointer;display:inline-flex;align-items:center;gap:8px;font-size:14px;padding:8px 12px;">` + `<Icon Name="@Icon.Names.Plus" Size="14" />` + text "Add photos" + `<InputFile multiple accept="image/jpeg,image/png,image/gif,image/webp" style="display:none;" />`
- At cap (`_photos.Count >= _settings.MaxPhotosPerRecipe`): disable the label (add `pointer-events:none; opacity:0.4;`) and show a `<CbChip>` with `background: var(--warn-soft); color: var(--warn);` reading "Max @_settings.MaxPhotosPerRecipe photos"

### Per-file upload progress feedback

When a multi-file upload is in progress (sequential foreach loop):
- Show an inline status line below the "Add photos" button: `<div role="status" aria-live="polite" style="font-size:12.5px;color:var(--ink-3);margin-top:8px;">Uploading @_uploadingFileName…</div>`
- After each file completes: `StateHasChanged()` re-renders the card grid immediately, providing per-file visual confirmation that the file has been saved (the card appears in the grid)
- On error for a file: fire `Toast.Show(...)` (existing toast pattern) and continue to next file — the status line clears for the next filename

### Paste-URL input

- `<CbInput Type="url" Placeholder="Or paste a photo URL (https://…)" AriaLabel="Paste photo URL" />`
- Inline below the file upload affordance
- On change: (1) `RecipePhotoUrlValidator.TryValidate`, (2) if valid, show `<div role="status" aria-live="polite">Validating…</div>`, then `await headValidator.ValidateAsync(url)`
- On accept: add to gallery, clear input
- On reject: inline error `role="alert"` in `color: var(--warn); font-size: 12.5px; line-height: 1.4;` — matches existing `RecipePhotoComposite.razor:70-73` error style

### AI "Suggest photo search terms" button

- Rendered only when `_aiOn == true` (gate: `CookBotSettings.AiFeaturesEnabled && UserProfile.AiEnabled`)
- `<CbButton Variant="Accent" StartIcon="@Icon.Names.Spark">Suggest photo search terms</CbButton>`
- When AI is off: **not rendered** (not just disabled — follows existing RecipeEditor AI gating pattern)
- Loading state: `disabled` + label becomes "Finding search terms…" + no spinner (matches existing AI button loading patterns in RecipeEditor)
- Output block (below the button, after response arrives):
  - Container: `<div class="cb-card" style="padding:16px;margin-top:8px;font-size:14px;color:var(--ink-2);line-height:1.5;" role="region" aria-label="Photo search suggestions">`
  - Content: plain text, pre-formatted (no markdown links, no `<a>` tags, no auto-linking)
  - Visual treatment: same `cb-card` surface as a recipe note, not a form — communicates "read this, don't click it"
  - If the output string contains a detectable URL (`Uri.TryCreate` scan), strip the URL from display and append: `(URL removed — AI suggestions are search terms only)`
  - Output is NOT persisted; it lives in component state only until next AI call or page navigation

### Copyright disclaimer

**Single visible disclaimer line, present at ALL TIMES in the editor photo section (not conditional, not a tooltip):**

```html
<div role="note"
     aria-label="Copyright notice"
     style="font-size:11.5px;color:var(--ink-3);line-height:1.4;margin-top:8px;">
    Only add photos you have the right to use.
    AI suggestions are search terms only — verify the license at the source.
</div>
```

This is rendered **once** at the bottom of the gallery manager component (below all inputs), not once per photo card. Source: `CONTEXT.md D-14-09`, GALLERY-04, P12.

The 11.5px / `var(--ink-3)` size/color matches the existing disclaimer line at `RecipePhotoComposite.razor:91-94` — reuse those inline-style properties verbatim. No `.photo-copyright-notice` class is used; all styling is inline to match the codebase convention in RecipeView and RecipeEditor where layout/text styles are inline within Razor markup.

### Delete confirmation

- Uses existing `CbConfirmDialog` component
- Title: "Delete photo?"
- Body: "This will permanently remove the photo@(isLocal ? " and its file" : "")."
- Confirm button: "Delete photo" (`cb-btn accent` — destructive action uses accent per existing pattern in `CbConfirmDialog`)
- Dismiss button: "Keep photo" (`cb-btn ghost`)

## Assumptions and Flags

**Assumption A1 — Icon rotation for up/down:**
The icon set has `ArrowL` and `ArrowR` (horizontal arrows). To produce up/down reorder arrows, apply `style="transform:rotate(-90deg)"` (up) and `style="transform:rotate(90deg)"` (down). If this is visually unacceptable at plan time, the alternative is to use the unicode arrows `↑` / `↓` as button text (which is what the RESEARCH.md code example uses). Both options are keyboard-accessible; the planner should pick one and stay consistent.

**Assumption A2 — Caption save timing:**
The spec says caption updates fire `RecipePhotoService.UpdateCaptionAsync` immediately (on blur / debounced on change). If the planner determines that caption should batch with the recipe save instead (to avoid frequent DB writes during editing), update the paste-URL "Validating…" and caption save feedback copy accordingly. The visual contract does not change.

**Assumption A3 — Single disclaimer position:**
The copyright disclaimer is rendered once at the bottom of `RecipePhotoGalleryManager`. If the planner splits the manager into multiple sub-components, ensure the disclaimer remains on every rendered surface (upload affordance surface, paste-URL surface, AI helper output surface). A single rendered instance is sufficient as long as all three input surfaces are within the same visual grouping.
