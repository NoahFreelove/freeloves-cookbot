<objective>
Add `PhotoUrlHeadValidator` — the Application-layer business-rule validator that, given a scheme-validated URL, issues an HTTP HEAD (with a 405→ranged-GET fallback) and accepts only on 2xx + `Content-Type: image/*`. This is the "HEAD-validated before persist" gate required by GALLERY-04 / D-14-10. No HEAD path exists today; this plan creates it as a standalone, testable unit so the UI and service plans can depend on a proven contract.

Purpose: GALLERY-04 makes HEAD-validation a hard gate that blocks persist on failure. Isolating it from the upload pipeline keeps it unit-testable against a mockable transport.
Output: `PhotoUrlHeadValidator.cs` + `PhotoUrlValidationResult`, the Singleton DI registration, and a unit test suite covering the accept/reject/fallback lanes.
</objective>

namespace CookBot.Application.Services;

public sealed record PhotoUrlValidationResult(bool IsValid, string? ErrorMessage)
{
    public static PhotoUrlValidationResult Valid => new(true, null);
    public static PhotoUrlValidationResult Timeout => new(false, "URL validation timed out — check the URL and try again.");
    public static PhotoUrlValidationResult NetworkError => new(false, "Could not reach the photo URL — check connectivity.");
    public static PhotoUrlValidationResult NotAnImage => new(false, "URL did not return an image — only image URLs are accepted.");
    public static PhotoUrlValidationResult HttpError(System.Net.HttpStatusCode sc) => new(false, $"Could not reach that URL (HTTP {(int)sc}).");
}

public class PhotoUrlHeadValidator
{
    // url MUST already have passed RecipePhotoUrlValidator (scheme allowlist) — this validator
    // only performs the network/content-type check. Never throws to the caller.
    public Task<PhotoUrlValidationResult> ValidateAsync(string url, CancellationToken ct = default);
}
</interfaces>
