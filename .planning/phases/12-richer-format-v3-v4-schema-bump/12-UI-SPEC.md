## New Surface Specifications

### 1. RecipeView — Equipment Checklist

**Location:** Inside the sticky `<aside>` sidebar, inserted after the Tags chip block (after line ~167 of RecipeView.razor). Only rendered when `_doc.Equipment.Count > 0`.

**Structure:**
```
<CbEyebrow> "Equipment" </CbEyebrow>       ← .eyebrow, 11px, --ink-3, margin-top:16px margin-bottom:8px
<ul role="list" aria-label="Equipment list">
  @foreach item:
    <li>
      <label class="cb-checkbox">
        <input type="checkbox" />           ← ephemeral; never persisted
        <span class="box" />                ← 18×18px rounded box per .cb-checkbox CSS
        <span>@item</span>                  ← 14px, --ink-2, weight 400
      </label>
    </li>
</ul>
```

- Checkbox state is component-local (`_checkedEquipment: HashSet<string>`), ephemeral (not persisted), resets on navigation.
- Checked item label: `text-decoration:line-through;color:var(--ink-4)` — mirrors the cooking-mode highlight-step convention (visual feedback only).
- Empty state: section is fully hidden (`@if (_doc.Equipment.Count > 0)`) — no empty-state copy needed.
- Keyboard: `<label>` wrapper makes the whole row keyboard-activatable via Enter/Space (native checkbox behavior). No custom key handlers needed.
- ARIA: `role="list"` on the container, `aria-label="Equipment list"`. Each `<label>` implicitly associates with its `<input>`. The `<input type="checkbox">` carries an implicit accessible name from the label text.
- Focus ring: `.cb-checkbox:focus-within .box` already defined in cookbot-design.css line 476: `box-shadow: 0 0 0 2px var(--accent-soft)`.

### 2. RecipeView — Substitution Sub-lines Under Ingredients

**Location:** Below each ingredient row `<div>` in the `@foreach (var ing in _doc.Ingredients)` loop (after line ~157 of RecipeView.razor). Only rendered when `ing.Substitutions.Count > 0`.

**Structure per ingredient:**
```
@if (ing.Substitutions.Count > 0)
{
    <div style="padding:4px 0 8px 0;border-bottom:1px solid var(--line);">
        @foreach (var sub in ing.Substitutions)
        {
            <div style="display:flex;align-items:baseline;gap:8px;margin-top:4px;padding-left:8px;">
                <span style="font-size:11px;color:var(--ink-4);flex-shrink:0;">or</span>
                <span style="font-size:13px;color:var(--ink-3);line-height:1.45;">
                    @(sub.Name != null ? $"{FormatSubAmount(sub)} {sub.Name}" : sub.Note)
                    @if (sub.Name != null && sub.Note != null) { <span> — @sub.Note</span> }
                </span>
            </div>
        }
    </div>
}
```

- Substitution amounts are display-only and DO NOT scale — `FormatSubAmount` renders `sub.Amount` + `sub.Unit` as static text; the servings multiplier is never applied (D-12-04).
- Visual hierarchy: "or" in `--ink-4` (11px), substitution text in `--ink-3` (13px) — subordinate to the parent ingredient row at 14px `--ink-2`.
- No chip wrapper — sub-lines use plain text to avoid chip visual weight competing with the parent ingredient. The "or" prefix makes the substitution relationship scannable without needing a badge.
- Empty state: hidden entirely when `ing.Substitutions.Count == 0`.
- ARIA: The substitution block has no explicit ARIA role; it is adjacent to the parent ingredient and semantically subordinate in DOM order. Screen readers read them inline.

`FormatSubAmount` helper: if `sub.Amount != null && sub.Unit != null` → `"{amount} {unit}"`, else if `sub.Amount != null` → `"{amount}"`, else `""`. Returns empty string when neither is present.

**Location:** Below the temperature display block within the `else if (step is ContentStep content)` branch (after line ~214 of RecipeView.razor). Only rendered when `content.DonenessCue` is non-null and non-empty.

**Structure:**
```
@if (!string.IsNullOrWhiteSpace(content.DonenessCue))
{
    <div style="margin-top:8px;display:inline-flex;align-items:center;gap:4px;
```

- Empty state: hidden entirely when null or whitespace.
- ARIA: no explicit role; rendered as inline flow text adjacent to temperature, screen reader reads in DOM order.

### 4. RecipeView — Provenance Credit

**Location:** Inside the `.recipe-hero` left column, immediately after the description `<p>` block (after the `_doc.Description` conditional at line ~67 of RecipeView.razor). Only rendered when `_doc.Provenance` is non-null AND at least one of `AuthorName` or `SourceName` is present.

**Copy contract:**
- `SourceName` and `AuthorName` both present: `"Adapted from {SourceName} by {AuthorName}"`
- `SourceName` only: `"Adapted from {SourceName}"`
- `AuthorName` only: `"By {AuthorName}"`
- When `SourceUrl` is present and passes `RecipePhotoUrlValidator` allowlist (http/https only): the entire credit string becomes a hyperlink `<a href="@_validatedSourceUrl" target="_blank" rel="noopener noreferrer">`.
- When `SourceUrl` is present but FAILS the allowlist: render as plain text, no `<a>` tag (D-12-08). A `_validatedSourceUrl` variable computed in `@code` via `RecipePhotoUrlValidator.TryValidate` controls this branch.
- When `SourceUrl` is null: render plain text regardless.

**Structure:**
```
@if (_doc.Provenance is { } prov && (prov.AuthorName != null || prov.SourceName != null))
{
    var credit = BuildProvenanceCredit(prov);   // → string, composition logic above
    <div style="margin-top:8px;">
        @if (_validatedSourceUrl != null)
        {
            <a href="@_validatedSourceUrl"
               target="_blank"
               rel="noopener noreferrer"
               style="font-size:14px;font-style:italic;color:var(--ink-3);text-decoration:underline;text-underline-offset:3px;">
                @credit
            </a>
        }
        else
        {
            <p style="font-size:14px;font-style:italic;color:var(--ink-3);margin:0;">@credit</p>
        }
    </div>
}
```

- `_validatedSourceUrl` is a computed `string?` field in `@code`, populated in `OnParametersSet`/`OnInitialized` by calling `RecipePhotoUrlValidator.TryValidate(prov?.SourceUrl, out _)` — if validation passes, store the URL; if not, null.
- Link target `_blank` with `rel="noopener noreferrer"` (standard external link safety).
- No separate empty state copy — the entire block is absent when provenance is null or both author/source are null.
- ARIA: link text is the credit string, which is descriptive enough. No `aria-label` needed.

### 5. RecipeEditor — Substitution Authoring (Sub-Rows Under Ingredient)

**Location:** Inside the ingredient loop in RecipeEditor.razor, added as an expandable sub-area below each ingredient row. The current row grid is `grid-template-columns:60px 70px 1fr 32px 28px`.

**Pattern:**
- A "Add substitution" ghost link/button appears at the end of each ingredient row when no substitutions exist.
- When substitutions exist, each one renders as an indented row below the parent ingredient row, inside the same wrapping `<div>` (outside the grid, spanning full width).
- Each substitution row: single `<input type="text">` for the `Note` (required freeform), with optional `Name` field. For Phase 12 scope (editor discretion per CONTEXT D-12 "Claude's Discretion"), a single `Note` input is sufficient — structured `Name`/`Amount`/`Unit` can be authoring-UI deferred.

**Structure per ingredient:**
```html
<!-- After the existing ingredient row div, before the next border-bottom -->
@if (ing.Substitutions is { Count: > 0 })
{
    @foreach (var (sub, si) in ing.Substitutions.Select((s,i)=>(s,i)))
    {
        <div style="display:grid;grid-template-columns:1fr 24px;gap:0;
                    background:var(--cream-2);border-bottom:1px solid var(--line);
                    padding:8px 16px 8px 24px;align-items:center;">
            <input type="text"
                   class="cb-input"
                   value="@sub.Note"
                   placeholder="Substitution note (e.g. oat milk for dairy-free)"
                   aria-label="@($"Substitution {si+1} for {ing.Name}")"
                   style="font-size:13px;padding:4px 8px;"
                   @oninput="@(e => OnSubstitutionNoteInput(ingIndex, si, e))" />
            <button type="button"
                    aria-label="Remove substitution"
                    style="background:transparent;border:0;color:var(--ink-4);cursor:pointer;
                           display:flex;align-items:center;justify-content:center;"
                    @onclick="@(() => RemoveSubstitution(ingIndex, si))">
                <Icon Name="@Icon.Names.Trash" Size="13" />
            </button>
        </div>
    }
}
<div style="padding:4px 16px 8px 24px;background:var(--cream-2);
            border-bottom:1px solid var(--line);">
    <button type="button"
            class="cb-btn ghost"
            style="font-size:12.5px;padding:4px 8px;height:24px;"
            @onclick="@(() => AddSubstitution(ingIndex))">
        <Icon Name="@Icon.Names.Plus" Size="11" /> Add substitution
    </button>
</div>
```

- `--cream-2` background for sub-rows visually indents them from the `--paper` parent row.
- 24px left padding creates visual indentation under the parent ingredient name column.
- `class="cb-input"` on the input for consistent focus ring (accent border + accent-soft shadow on `:focus-visible`).
- ARIA: each input has `aria-label` with substitution index and parent ingredient name.
- Keyboard: Tab navigates through substitution inputs in DOM order; Enter in the last substitution input triggers add-substitution (optional convenience, can be omitted for Phase 12 simplicity).

### 6. RecipeEditor — Equipment List Authoring

**Location:** New `<CbCard Padding="18">` in the right rail `<aside>`, inserted after the Tags card (after line ~300 of RecipeEditor.razor). Mirrors the Tags card pattern exactly.

**Structure:**
```razor
<CbCard Padding="18">
    <CbEyebrow><div style="margin-bottom:8px;">Equipment</div></CbEyebrow>
    <div style="display:flex;gap:8px;flex-wrap:wrap;margin-bottom:8px;">
        @if (_equipment.Count == 0)
        {
            <span style="font-size:12.5px;color:var(--ink-3);">No equipment yet.</span>
        }
        else
        {
            @foreach (var item in _equipment.ToList())
            {
                var captured = item;
                <span class="cb-chip tag" style="cursor:default;">
                    @captured
                    <button type="button"
                            aria-label="@($"Remove {captured}")"
                            style="background:transparent;border:0;color:inherit;cursor:pointer;
                                   font-size:14px;line-height:1;padding:0 0 0 4px;
                                   display:inline-flex;align-items:center;"
                            @onclick="@(() => RemoveEquipment(captured))">×</button>
                </span>
            }
        }
    </div>
    <input type="text"
           value="@_equipmentInput"
           placeholder="add equipment…"
           aria-label="Add equipment item"
           style="width:100%;padding:8px 12px;border-radius:8px;border:1px solid var(--line);
                  background:var(--cream);font-family:inherit;font-size:13px;outline:none;"
           @oninput="OnEquipmentInputInput"
           @onkeydown="OnEquipmentInputKeyDown" />

```

- Pressing Enter or comma in the input commits the item as a chip (same pattern as Tags input).
- `cb-chip tag` variant (transparent bg + border) distinguishes equipment from ingredient chips (`cb-chip ing`).
- Empty state: `"No equipment yet."` in `--ink-3` at 12.5px — matches the Tags card empty state copy verbatim.
- Duplicate items: silently ignored (case-insensitive match before add, same as tags dedup).
- `×` remove button: same shape as Tags card remove button.
- ARIA: the `<input>` has `aria-label="Add equipment item"`. Each chip `<button>` has an `aria-label` naming the item.
- Focus ring: the `<input>` border turns `--accent` on `:focus-visible` (inline style `outline:none` + the existing border transition; matches the Tags input at RecipeEditor line 297).

- ARIA: each input has a `for`/`id` label association. URL warning has `role="alert"`.
