<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser DOM (contenteditable) → Blazor Server circuit | The user's typed characters cross from JS into .NET via `dotNetRef.invokeMethodAsync("OnSegmentInputFromJs", ...)`. The text is fully attacker-controlled by the recipe author (multi-user trusted-LAN posture per CLAUDE.md). |
| Browser DOM (keydown event) → Blazor Server circuit | The user's keystrokes cross via `OnSegmentKeyDownFromJs`. Caret offset is read from `window.getSelection()` (browser-controlled, but spec-bounded — non-negative integer). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03P05-01 | Tampering | OnSegmentInputFromJs | mitigate | Input segmentIndex is bounds-checked against `_renderTokens.Count` before dereferencing; `IsChip` guard prevents writing chip-typed tokens; resulting Text flows through `OnTextChanged` → `RecipeStepEditor.OnTextChanged` → existing Phase 1 validator gate on save (no new persistence path). |
| T-03P05-02 | Information Disclosure | DotNetObjectReference lifetime | mitigate | `_dotNetRef` is created per-component instance, disposed in `IAsyncDisposable.DisposeAsync`. No cross-circuit/cross-user reference sharing. Each user's editor instance owns its own ref. |
| T-03P05-03 | Denial of Service | OnSegmentInputFromJs | accept | A malicious script in the page could hammer `invokeMethodAsync` with large payloads. Trusted-LAN posture (multi-user but not internet-exposed per CLAUDE.md) means this is a stability concern, not a security one. The existing Blazor Server circuit framing already enforces a max message size; we inherit that protection. |
| T-03P05-04 | Spoofing | OnSegmentKeyDownFromJs key parameter | accept | The `key` string ("Backspace", "ArrowLeft") is browser-emitted — trustworthy at the spec level. Even if spoofed via console, the worst case is an unintended chip removal (recoverable via Ctrl-Z in normal use, or by re-saving). Not a security threat in trusted-LAN posture. |
| T-03P05-05 | Elevation of Privilege | JSInvokable surface | mitigate | Both new JSInvokables are `public async Task` / `public async Task<bool>` on a per-component instance — they are NOT static, NOT cross-component callable. The Blazor JSInvokable plumbing scopes invocations to the originating DotNetObjectReference. No path for one user's circuit to invoke another user's chip composer. |
