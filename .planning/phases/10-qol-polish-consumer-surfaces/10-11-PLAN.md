## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user → grocery list | PantryView surfaces the user's own pantry items; the click path uses CurrentUserService.CurrentUserId as the userId for EnsurePrimaryListAsync |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-11-01 | Tampering | Cross-user grocery list write | mitigate | `EnsurePrimaryListAsync(userId)` filters by userId; the returned list always belongs to the current user. AddItemAsync looks up the list by groceryListId — if a caller passes another user's listId, they would write to that list, but the Web call site at PantryView only passes the result of EnsurePrimaryListAsync(currentUserId), so this surface cannot be exploited from PantryView. (Future API callers must replicate the userId chain.) |
| T-10-11-02 | Information Disclosure | Pantry ingredient leak via toast | accept | Toast displays the item's own name; this is data the user already sees in PantryView |
</threat_model>
