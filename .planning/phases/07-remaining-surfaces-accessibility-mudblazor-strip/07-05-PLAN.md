# Plan 07-05: Profile + user/sharing dialogs migration

## Goal
Rewrite `EditProfile.razor` against Phase 5 atoms. Migrate user-management and sharing dialogs.

## Tasks

### Task 1: EditProfile.razor (PROF-01)
Settings grouped into `<CbCard>` cards:
1. **Display name** — CbInput bound to user.DisplayName + Save button
2. **API key** — CbInput (type=password) bound to UserProfile.AiApiKey + Save button + "Manage shared keys" link → opens `SharedKeysDialog` via `CbDialogService`
3. **AI features** — `<CbToggle>` bound to `UserProfile.AiEnabled`. Toggling persists immediately. Description text explains "When off, all AI surfaces are hidden across the app."
4. **Theme & density** — Density toggle (`CbToggle` bound to UserProfile.Density or similar; if no field exists, store in localStorage and apply via `cookbot.setDensity(...)` JS interop). Per Phase 5 D-05.
5. **Equipment** — list of equipment items, add/remove
6. **Dietary preferences** — list of preferences, add/remove

### Task 2: Migrate profile dialogs
For `AddUserDialog.razor`, `AdminManageUsersDialog.razor`, `PasswordPromptDialog.razor`, `SharedKeysDialog.razor`:
- Migrate to `<CbDialog>` slots
- Update call sites:
  - `TopBar.razor`'s user-switcher: replace MudBlazor `IDialogService` with `CbDialogService` for `PasswordPromptDialog`
  - `TopBar.razor`'s admin "Manage users" button: same for `AdminManageUsersDialog`
  - `MainLayout.razor` cleanup: remove the `IDialogService` injection that was the Phase 5 Alternative A carve-out

Note: this task removes the last MudBlazor `IDialogService` consumers. After this plan, ONLY the `<MudThemeProvider>` / `<MudPopoverProvider>` / `<MudDialogProvider>` / `<MudSnackbarProvider>` providers remain in MainLayout — Plan 07-07 strips those.

### Task 3: Build verify + commit
- `dotnet build` clean
- `dotnet test` baseline
- Atomic commit
