## Spacing Scale

All values are multiples of 4 from the standard set {4, 8, 16, 24, 32, 48, 64}.

| Token | CSS / Value | Usage in Nutrition Panel |
|-------|-------------|--------------------------|
| xs | 4px | Gap between confidence badge and ingredient name; icon-to-text gap; toggle container padding and gap |
| sm | 8px | `var(--gap)` compact / gap between macro stat tiles on narrow; between toggle options; coverage list row padding; stale banner margin-top |
| md | 16px | `var(--pad-sm)` — padding inside the panel card; gap between section rows; stale banner padding; CTA button padding |
| lg | 24px | `var(--pad)` — outer padding of the panel card (matches recipe-article padding rhythm) |
| xl | 32px | Margin-top separating the nutrition section from the recipe body grid |
| 2xl | 48px | Visual separation from the preceding last-cook callout or method section |

Exceptions:
- The macro stat row uses a 4-column grid with `gap: 16px` (md) at desktop and collapses to 2-column with `gap: 8px` (sm) at ≤720px, matching the recipe-body-grid collapse breakpoint.
- Coverage list rows use `padding: 8px 0; border-bottom: 1px solid var(--line)` — the same rhythm as the ingredient sidebar rows in RecipeView (RecipeView.razor:231).
- The disclaimer line uses `margin-top: 16px` (md) and no padding beyond the card's own padding.

## State Machine: Panel Visual Contract

The nutrition panel is a **5-state machine**. Each state occupies the same DOM region (below the recipe body grid, inside `recipe-article`).

### State 1: Not Yet Calculated (null cache)

Layout: A single `cb-card` (padding: 24px) containing:
1. `CbEyebrow` — "Estimated nutrition"
2. A quiet body line at 14px, `color:var(--ink-3)`: "Nutrition not yet calculated."
3. The "Calculate nutrition" CTA button — `CbButton Variant=Accent`, Icon `Icon.Names.Flame` (or the project's closest analytical icon; use `Icon.Names.Scale` if Flame is reserved for cooking). Full-width=false; aligned left.
4. The non-dismissable disclaimer (always present, even in this state — see §Disclaimer Pattern).

No skeleton, no spinner, no placeholder numbers. The pre-calc state is minimal by design: the CTA is the dominant element.

### State 2: Calculated (current cache, IsStale=false)

Layout: A `cb-card` (padding: 24px) containing, in order:

**2a. Panel header row** — flex row, align-items baseline, justify-content space-between:
- Left: `CbEyebrow` — "Estimated nutrition"
- Right: Per-serving/total segmented toggle (see §Toggle Contract)

**2b. Macro stat row** — 4-column CSS grid (columns: repeat(4,1fr); gap: 16px; margin-top: 16px):
Each cell:
```
<div class="num" style="font-size:28px;font-weight:600;color:var(--accent);">
    {value}
</div>
<div style="font-size:12.5px;color:var(--ink-3);font-weight:400;">
    {unit}  ·  {name}
</div>
```
Columns (left to right): Energy (kcal) · Protein (g) · Carbs (g) · Fat (g)

Values: per-serving when toggle is "Per serving"; totals when "Total".
Tabular numerals mandatory (`class="num"`).
Whole numbers: 0 decimal places for kcal. One decimal place for macros (e.g. "12.5").

At ≤720px: 2-column grid, gap: 8px. Energy + Protein on row 1; Carbs + Fat on row 2.

**2c. Horizontal rule** — `<hr class="cb-rule" style="margin:16px 0;">` (matches recipe body grid section dividers)

**2d. Coverage summary** — 12.5px, `color:var(--ink-3)`, margin-bottom: 16px:
"Matched {n} of {total} ingredients"

**2e. Coverage list** — an expandable list of all ingredients with their match results. Default: collapsed (show only unmatched + low-confidence rows visible, matched rows hidden behind a "Show all matches" toggle link). Expanded: all rows visible.

Each row (padding: 8px 0; border-bottom: 1px solid var(--line)):
```
[confidence badge]  [ingredient name]             [kcal value or --]
                    [CNF description · FoodId]
```

Row layout: flex, align-items baseline, gap: 8px.

Confidence badge (uses existing `.cb-chip` geometry, `.cb-badge` weight):
- HIGH: `.cb-chip.cb-badge.cb-badge-in-stock` — green tint (var(--green-soft)/var(--green))
- MEDIUM (≈): `.cb-chip.cb-badge.cb-badge-low` — amber tint (var(--warn-soft)/var(--warn)); prepend "≈" to the kcal value
- UNMATCHED: `.cb-chip.cb-badge.cb-badge-out` — neutral tint (ink-4); value shows "--" in `color:var(--ink-4)`

Ingredient name: 14px, `color:var(--ink-2)`, font-weight 400.
CNF description + FoodId: 12.5px, `color:var(--ink-4)`, shown on the second line below the ingredient name. Format: "{CnfFoodDescription} [{FoodId}]". Hidden when UNMATCHED (no match to show).
kcal value (right-aligned, tabular): `class="num"`, 14px, `color:var(--ink-2)`. Shows "--" for UNMATCHED.

"Show all {n} matches / Hide" toggle: a plain `<button class="cb-btn ghost">` at 12.5px shown below the list when there are matched rows to reveal. Click triggers `StateHasChanged()` — no server round-trip.

**2f. Disclaimer** — always present (see §Disclaimer Pattern).

### State 3: Stale (IsStale=true, cached values exist)

Layout: Same as State 2, but with an additional stale-state banner inserted between the panel header row and the macro stat row:

```html
<div role="status" aria-live="polite"
     style="display:flex;align-items:center;gap:8px;
            background:var(--warn-soft);border-radius:var(--t-radius-sm);
            padding:8px 16px;margin-top:8px;font-size:14px;color:var(--warn);">
    <Icon Name="@Icon.Names.Clock" Size="14" />
    Recipe has changed — values may be outdated.
    <CbButton Variant=Ghost style="margin-left:auto;">
        Recalculate nutrition
    </CbButton>
</div>
```

The stale macro values remain visible (dimmed at `opacity:0.7`) beneath the banner so the user has context while deciding whether to recalculate. The "Recalculate nutrition" affordance is inside the banner — non-blocking, always available, never auto-triggered.

The "Recalculate nutrition" CTA is a Ghost variant button (not Accent) to distinguish it from the primary "Calculate nutrition" CTA in State 1. The distinction: State 1 has no data; State 3 has stale data.

### State 4: Calculating (in-progress)

Layout: Same as State 1, but the CTA button is disabled and shows a quiet inline busy state:

```html
<CbButton Variant=Accent Disabled=true>
    <span class="cb-pulse">Calculating…</span>
</CbButton>
```

`cb-pulse` is the existing `0%,100% opacity:1 / 50% opacity:0.3` keyframe animation (cookbot-design.css:689).

No blocking overlay, no full-card skeleton. The panel area is static (State 1 layout with the button disabled). SignalR round-trips for a local SQLite compute are expected to be fast (< 1 second); the pulse animation is a belt-and-suspenders guard for slow machines.

### State 5: Error (NutritionService.ComputeAsync threw / DB error / timeout)

Layout: A single `cb-card` (padding: 24px) containing:
1. `CbEyebrow` — "Estimated nutrition" (heading unchanged, same as all states).
2. An error banner:

```html
<div role="status" aria-live="polite"
     style="display:flex;align-items:center;gap:8px;
            background:var(--error-soft);border-radius:var(--t-radius-sm);
            padding:8px 16px;margin-top:8px;font-size:14px;color:var(--error);">
    <Icon Name="@Icon.Names.Alert" Size="14" />
    Nutrition calculation failed — try again.
</div>
```

3. The "Try again" CTA button — `CbButton Variant=Accent`, aligned left, margin-top: 16px. Clicking retries `NutritionService.ComputeAsync` and transitions back to State 4 (Calculating). Never a dead end.
4. The non-dismissable disclaimer (always present — see §Disclaimer Pattern).

Rules:
- `role="status"` / `aria-live="polite"` on the error banner — consistent with the stale banner pattern (State 3).
- The panel never stays permanently in State 5 — the "Try again" CTA is always rendered and reachable.
- If a stale cache exists when the error occurs, the stale values are NOT shown (unlike State 3). The error state is entered fresh from State 4; no cached data is visible to avoid showing numbers that may be from an inconsistent state.
- On successful retry: transitions to State 2 (Calculated, IsStale=false).

## Toggle Contract: Per-Serving / Total

The per-serving/total toggle is a segmented control — two adjacent pill buttons that act as a radio group. Not a `<select>`, not a `CbToggle` (which is a boolean switch). Implementation: two `<button>` elements sharing a flex container.

```
[ Per serving ]  [ Total ]
```

- Container: `display:flex; border:1px solid var(--line-strong); border-radius:999px; padding:4px; gap:4px;`
- Each option: `<button class="cb-btn subtle">` when inactive; `<button class="cb-btn accent">` when active.
- Height: 32px (padding: 8px 16px). Font-size: 14px. Font-weight: 400.
- Default active: "Per serving" (D-15-15).
- Focus ring: 2px solid var(--accent), outline-offset 2px (inherits from .cb-btn:focus-visible in cookbot-design.css:702).
- Keyboard: `role="radiogroup"` on the container; `role="radio"` + `aria-checked` on each button. Arrow keys move focus (handled via @onkeydown).
- On toggle: `StateHasChanged()` only — no server round-trip. Values are pre-loaded in both per-serving and total from `RecipeNutritionCache`.

## Disclaimer Pattern

The disclaimer is a `role="note"` block. It mirrors the Phase 14 copyright disclaimer pattern exactly (RecipePhotoGalleryManager.razor:225–231):

```html
<div role="note"
     aria-label="Nutrition data notice"
     style="font-size:12.5px;color:var(--ink-3);line-height:1.4;margin-top:16px;">
    Estimated nutrition — not suitable for medical dietary planning.
    Data: Health Canada, Canadian Nutrient File (2015).
</div>
```

Rules:
- Present in ALL five panel states — always rendered, never conditional, never dismissable.
- Color: `var(--ink-3)` — NOT `var(--ink-4)` (would fail WCAG AA on cream surfaces).
- Font-size: 12.5px. WCAG AA passes at var(--ink-3) on var(--paper) and var(--cream-2) (contrast ratio ≥ 4.5:1 verified).
- No icon, no border, no background. Plain prose — legally required but typographically quiet.
- Must not imply Health Canada endorsement (the word "Data:" frames it as attribution, not sponsorship).
- The verbatim copy is locked (D-15-17, SC4). Do not paraphrase, split, or abbreviate.

## Panel Placement in RecipeView

The nutrition panel renders inside `<article class="recipe-article">` (max-width:1080px, padding:24px 32px 80px), **below** the `recipe-body-grid` div and **below** the last-cook callout (if present). It is full-width (spanning both grid columns), not inside the sidebar or the method column.

```
recipe-article
  └─ recipe-hero            (photo + meta stats)
  └─ recipe-body-grid
      ├─ <aside>            (ingredients sidebar)
      └─ <div>              (method steps + last-cook callout)
  └─ [nutrition panel]      ← HERE: margin-top: 48px (2xl) from body grid
```

Margin-top: 48px (`--space-2xl` equivalent) from the `recipe-body-grid`. This matches the existing 48px `margin-bottom` on the `recipe-hero`. The section break reads visually as a new zone, not a continuation of the method.

At ≤720px: the panel collapses to single-column naturally (it was already full-width). Padding adjusts to `16px 16px` per the existing `.recipe-article` media query.

The panel is wrapped in a conditional:
```razor
@if (_doc != null && _recipe != null)
{
    @* ... existing hero + body ... *@
    @* Nutrition panel *@
    <section aria-label="Estimated nutrition" style="margin-top:48px;">
        @* panel card here *@
    </section>
}
```

The `<section>` has `aria-label="Estimated nutrition"` so screen readers announce the region.
