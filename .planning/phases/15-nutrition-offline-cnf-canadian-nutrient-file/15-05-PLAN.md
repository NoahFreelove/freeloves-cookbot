<objective>
Build the offline nutrition compute engine (NUTR-02/03/04): `NutritionService.ComputeAsync` matches ingredient names to CNF foods (token-intersection scoring over the pre-normalized descriptions), converts each amount to grams (CNF conversion factor first with US-cup scaling, then curated density fallback, then direct for mass units), scales the per-100g macros, sums totals, divides by `Servings`, and writes `RecipeNutritionCache` with per-ingredient match detail. It is called ONLY on an explicit user CTA (Plan 07) — never from the save path. Separately, `RecipeService` gets a SHA-256 content hash + `IsStale` mark on each canonical write, with NO dependency on `NutritionService` (P7).

Purpose: The heart of the feature — and the two hardest invariants: the flour→455 anchor (SC3) and "save never blocks on nutrition" (SC1/P7). Coverage is honest: unmatched → null (UI "--"), low-confidence → MEDIUM (UI "≈"), with the CNF FoodId+description always stored (SC2/P4).
Output: `INutritionService`, `NutritionService`, Infrastructure DI, RecipeService stale-mark, and the service test suite (flour anchor, unmatched-not-zeroed, stale-on-change, cup-scale, mass-direct, coverage counts).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| recipe ingredient names → CNF matcher (EF queries) | Untrusted recipe text is normalized then used in LINQ/EF queries — must be parameterized (no string-concatenated SQL) and bounded (no compute-DoS for many-ingredient recipes). |
| caller → ComputeAsync(recipeId, userId) | Access-control boundary: only the recipe owner may compute/read nutrition for it. |
| save path → nutrition | Display-only invariant: the save path must not call nutrition compute. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-15-10 | Elevation of Privilege | NutritionService.ComputeAsync / GetCacheAsync | mitigate | AssertOwnershipAsync (recipe → cookbook → cookbook.UserId == userId, else UnauthorizedAccessException) gates both methods — copied verbatim from RecipePhotoService (ASVS V4). |
| T-15-11 | Tampering (SQLi) | Ingredient name → EF query | mitigate | All matching is in-memory token scoring over EF entities loaded via parameterized LINQ (no raw SQL, no string concatenation); EF parameterizes all queries. |
| T-15-12 | Denial of Service | Many-ingredient recipe × 5,690-food scan | mitigate | CnfFoods are loaded once per compute (AsNoTracking) and scored in-memory; work is O(ingredients × foods) bounded and runs off the explicit CTA only (not on every save/render). No unbounded recursion or backtracking. |
| T-15-13 | Tampering | RecipeService writing nutrition into canonical / blocking save | mitigate | RecipeService only writes a SHA-256 hash + IsStale via IRepository<RecipeNutritionCache>; it has zero NutritionService dependency (grep-asserted). Nutrition is never written into CanonicalDocumentJson (P7/P15/SC1). |
| T-15-SC | Tampering | npm/pip/cargo installs | accept | No packages installed; BCL SHA256 + EF Core + System.Text.Json only. |
</threat_model>
