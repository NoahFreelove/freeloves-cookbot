<objective>
Produce the bundled, offline Canadian Nutrient File (CNF) seed artifact that the runtime app trusts (NUTR-01). A one-time offline Python script calls the three CNF REST API endpoints, subsets to energy + 3 macros (NutrientNameIDs 208/203/204/205), merges on `food_code`, and writes two committed JSON files under `seeds/nutrition/`. This is the supply-chain root of the nutrition feature: at runtime the app reads only these files — never the CNF API.

Purpose: Decouple the heavy, intermittently-available CNF REST API from the runtime path so nutrition works fully offline with no API key (SC1). The committed JSON is the integrity boundary — it ships verbatim, version-pinned to the CNF 2015 edition.
Output: `tools/build-cnf-seed.py`, `tools/README-cnf-seed.md`, `seeds/nutrition/cnf_foods.json`, `seeds/nutrition/cnf_conversion_factors.json`.
</objective>

    (1) VERIFY-BEFORE-TRUST: before building, call `https://food-nutrition.canada.ca/api/canadian-nutrient-file/nutrientname/?lang=en&type=json` and assert NutrientNameID 208 maps to "ENERGY (KILOCALORIES)" (kCal), 203→"PROTEIN" (g), 204→"FAT (TOTAL LIPIDS)" (g), 205→"CARBOHYDRATE, TOTAL (BY DIFFERENCE)" (g). <threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CNF REST API → seed files (build-time only) | Untrusted external data crosses here ONCE, offline, during development. The committed JSON is the integrity boundary the runtime trusts. |
| seed files → runtime app | The app trusts `seeds/nutrition/*.json` as authoritative reference data; no runtime fetch. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-15-01 | Tampering | CNF seed provenance / supply chain | mitigate | Seed is built once offline by `tools/build-cnf-seed.py` from the official Health Canada CNF REST API, version-pinned to the CNF 2015 edition, merged on `food_code`, stored verbatim, and committed to the repo. README documents the source + edition. Runtime makes no CNF API calls (no SSRF surface). |
| T-15-02 | Tampering | Wrong NutrientNameID → systematically wrong nutrition | mitigate | Verify-before-trust step asserts 208/203/204/205 against the live `nutrientname` endpoint and exits non-zero on mismatch — a wrong-ID seed cannot be silently built. |
| T-15-03 | Information Disclosure | CNF API call from runtime | accept→mitigate | No runtime HTTP path exists (D-15-03); the only CNF call is the dev-time build script. Trusted-LAN posture; no secrets, no PII in nutrition data. |
| T-15-SC | Tampering | npm/pip/cargo installs | mitigate | No new NuGet packages (hard invariant). The Python build script uses only `requests`/`json` from a dev environment and is NOT a runtime dependency — no package added to the .NET app. |
</threat_model>
