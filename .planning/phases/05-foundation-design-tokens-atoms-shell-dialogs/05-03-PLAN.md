Two-way binding pattern (Blazor standard):
  - `[Parameter] public T Value { get; set; }`
  - `[Parameter] public EventCallback<T> ValueChanged { get; set; }`
  - In handler: `await ValueChanged.InvokeAsync(newValue);`
  - Caller: `<CbToggle @bind-Value="_flag" />`

CbRadio handles a value-set:
  - `[Parameter] public TValue? CurrentValue { get; set; }` (the @bind-Value)
  - `[Parameter] public TValue Value { get; set; }` (the value this radio represents)
  - Selected when `EqualityComparer<TValue>.Default.Equals(CurrentValue, Value)`
  - On click: invoke `ValueChanged` with `Value`

CbSelect + CbOption pattern (Blazor idiomatic):
  - CbSelect renders a native `<select @onchange="…">` with class `cb-select`
  - CbSelect's ChildContent slot is where CbOption children land
  - CbOption renders `<option value="@SerializeValue()">…</option>` and gets the parent's TValue via CascadingParameter or directly registers its option string into a list. Simplest path: each CbOption renders its own `<option>` with `value` and `selected` set; CbSelect hooks `@onchange` to convert the string back to TValue via `EventCallback<string>`.

Decision for this plan (because Blazor's native binding to `<select>` only handles primitive value types cleanly): CbSelect TValue is constrained to `string`, `int`, `int?`, `bool`. For Phase 5 the sandbox demo binds to `string`. If Phase 6/7 needs richer types, we add a converter or use the index-based pattern; not in scope here.

**CbSelect.razor** (D-17, ATOM-10):
```razor
@namespace CookBot.Web.Components.Atoms
@typeparam TValue

<select class="cb-select" disabled="@Disabled" @onchange="HandleChange">
  @if (!string.IsNullOrEmpty(Placeholder))
  {
    <option value="" disabled selected="@(Value is null)">@Placeholder</option>
  }
  <CascadingValue Value="@(this)" IsFixed="true">
    @ChildContent
  </CascadingValue>
</select>

@code {
    [Parameter] public TValue? Value { get; set; }
    [Parameter] public EventCallback<TValue?> ValueChanged { get; set; }
    [Parameter] public string? Placeholder { get; set; }
    [Parameter] public bool Disabled { get; set; }
    [Parameter] public RenderFragment? ChildContent { get; set; }

    internal bool IsSelected(TValue candidate) =>
        Value is not null && EqualityComparer<TValue>.Default.Equals(Value, candidate);

    private async Task HandleChange(ChangeEventArgs e)
    {
        var raw = e.Value as string;
        var converted = ConvertFromString(raw);
        Value = converted;
        await ValueChanged.InvokeAsync(converted);
    }

    private TValue? ConvertFromString(string? raw)
    {
        if (raw is null) return default;
        var t = typeof(TValue);
        if (t == typeof(string)) return (TValue)(object)raw;
        if (t == typeof(int)) return int.TryParse(raw, out var i) ? (TValue)(object)i : default;
        if (t == typeof(int?)) return int.TryParse(raw, out var i) ? (TValue)(object)i : default;
        if (t == typeof(bool)) return bool.TryParse(raw, out var b) ? (TValue)(object)b : default;
        if (t.IsEnum) return Enum.TryParse(t, raw, out var en) ? (TValue?)en : default;
        // Fallback: try Convert.ChangeType for primitives
        try { return (TValue?)Convert.ChangeType(raw, t); }
        catch { return default; }
    }
}
```

**CbOption.razor** (D-17, ATOM-10):
```razor
@namespace CookBot.Web.Components.Atoms
@typeparam TValue

<option value="@SerializeValue()" selected="@IsSelected">
  @if (ChildContent != null) { @ChildContent } else { @Label }
</option>

@code {

    [Parameter, EditorRequired] public TValue Value { get; set; } = default!;
    [Parameter] public string? Label { get; set; }

    private bool IsSelected => Parent is not null && Parent.IsSelected(Value);

    private string? SerializeValue() => Value?.ToString();
}
```

CbOption registers via CascadingParameter to know which parent CbSelect it belongs to (for the `IsSelected` calculation). This is the simplest robust pattern; it works for the sandbox demo and Phase 6/7 needs (string/int/enum binding).

NOTE: Razor's `<select>` natively re-emits the value when an `<option>` is clicked, so `@onchange` on the parent fires with the option's `value` attribute as a string. CbSelect's `ConvertFromString` handles common types.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → Server (existing) | Form atoms bridge user input from the browser to server-side Razor state via Blazor Server's SignalR circuit (anti-forgery already configured by `app.UseAntiforgery()` in `Program.cs`). No new endpoints, no new auth gates. |
| Component parameter surface | `CbInput.Value` / `CbTextarea.Value` / `CbSelect.Value` accept user input via the browser. Existing Blazor framework HTML-escapes values when re-rendering (`value="@Value"` writes attribute-escaped). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-03-01 | XSS via attribute injection | CbInput/CbTextarea/CbSelect | mitigate | Razor escapes attribute values by default (`value="@Value"`). User-supplied strings cannot break out of the attribute. No `MarkupString` usage anywhere in the form atoms. |
| T-05-03-02 | Type-confusion in CbSelect.ConvertFromString | CbSelect | mitigate | The converter handles each TValue type explicitly (string, int, int?, bool, enum). Unknown types fall back to `Convert.ChangeType` inside a try/catch — failure returns `default(TValue)` rather than throwing. No code path returns user input as TValue without conversion. |
| T-05-03-03 | DOM-based XSS via uncontrolled `placeholder` | CbInput/CbTextarea/CbSelect | mitigate | `placeholder` is a Razor parameter rendered via `placeholder="@Placeholder"` — attribute-escaped. Callers passing dynamic placeholders (rare; Phase 6/7 will pass static strings) cannot inject HTML. |
| T-05-03-04 | Form-atom state leakage between sessions | All form atoms | accept | Form atoms hold no state beyond their bound `Value` parameter. State lives in the calling component's circuit-scoped fields. Blazor Server's per-circuit isolation already prevents cross-session leakage. |
