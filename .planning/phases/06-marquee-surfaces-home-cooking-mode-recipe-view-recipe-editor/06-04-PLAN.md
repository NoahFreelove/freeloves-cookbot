# Plan 06-04: Recipe Editor rewrite

## Goal
Rewrite `Components/Pages/RecipeEditor.razor` against Phase 5 atoms per design handoff `screens/recipe-editor.jsx`. Absorbs v1.1 Phase 3 EDITOR-01..07 — chip composer with `@`-trigger autocomplete, step/section toggle, timer suggestion, immutable id reorder, paste-raw-text routing, cooking-mode link-only highlight, keyboard a11y. Built once, in custom Razor, on top of the new shell.

## Tasks

### Task 1: Survey existing RecipeEditorParts
Examine `src/CookBot.Web/Components/Pages/RecipeEditorParts/`:
- `IngredientChip.razor`, `TimerChip.razor`, `RecipeChipComposer.razor`, `RecipeStepEditor.razor`, `InlineTimerSuggestion.razor`, `SectionDropConfirmationDialog.razor`
- These were partial v1.1 Phase 3 work. Read each, classify: KEEP (port to custom Razor with same logic), REWRITE (markup is too MudBlazor-heavy), DELETE (superseded by new design).
- Check for `wwwroot/js/recipe-chip-composer.js` — if present, port; if absent, create it per `.planning/phases/03-editor-ux-without-special-syntax/03-01-PLAN.md` design (read that plan for the JS interop API: `composer.init(elementRef, dotnetRef, { triggerChar: '@', ingredients: [...] })`, `composer.serialize() → string`, `composer.insertChip(name, id)`, `composer.destroy()`).

### Task 2: Borderless title/subtitle (ED-01)
Top of page: `<input>` for title (38px, font-weight 600, transparent bg, no border) bound to `RecipeDocument.Title`; below it `<input>` for description (15px, ink-2 color, transparent) bound to `RecipeDocument.Description`. Striped photo placeholder (180px tall) below subtitle.

Right rail (320px) with 4 meta cards (CbCard each):
1. **Cookbook** — selector showing current cookbook with chevron-down; opens a CbDropdown to switch
2. **Times & servings** — Active / Total / Serves rows with editable values
3. **Tags** — chip row of current tags (each with × to remove) + "add tag…" CbInput
4. **AI suggestions** — accent-soft bg, CbButton "Apply" — HIDDEN when AI off

### Task 3: Ingredients table (ED-02, ED-06)
CbCard wrapping a grid table:
- Header row (eyebrow): no header — implicit
- Each ingredient row: grid `60px 70px 1fr 28px` (qty / unit / name / actions)
- Each cell is a borderless input bound to `RecipeIngredient.Quantity` / `Unit` / `Name`
- Row separators: 1px var(--line)
- "Add ingredient" footer button (CbButton ghost full-width)
- Tab/Shift+Tab navigates fields within a row, then to next row's qty
- Backspace on empty row deletes that row
- Drag handle (or up/down buttons) to reorder — preserves immutable `RecipeIngredient.Id` (ED-06)

### Task 4: Step composer (ED-03, ED-04, ED-05)
Below ingredients, an "Add step" + a list of step CbCards. Each step CbCard contains:
- Step number circle (cream-2 bg, 30px, tabular numeral)
- Step type toggle (CbRadio group: "Step | Section header") — ED-04
- If "Step" selected: chip-aware contenteditable text editor (ED-03):
  - Mounts `recipe-chip-composer.js` interop on initial render
  - Typing `@` triggers ingredient autocomplete (custom dropdown showing `RecipeDocument.Ingredients`)
  - Selecting an ingredient inserts an `<IngredientChip>`-styled element with `data-id="@id"`
  - Visual chip = accent-soft bg + ingredient name
  - Underlying serialized text on save = `[name](#id)` markdown (JS interop converts contenteditable → markdown)
  - Embedded `<TimerChip>` elements for `step.TimerMinutes` (rendered by JS interop or as inline static nodes)
  - **Inline timer suggestion banner** (ED-05): when a numeric+min pattern is detected in typed text, show a non-modal banner above the step: "Detected 25 min — convert to a timer? [Yes / No]". Yes inserts a TimerChip; No dismisses. Saving never auto-rewrites.
- If "Section" selected: just a CbInput for the heading text (no chip composer, no timer controls)
- "more" actions menu (delete / move up / move down)

### Task 5: Paste-raw-text dialog (ED-07)
Editor's top-right area has a "Paste raw text" CbButton ghost. On click, opens existing `PasteRawTextDialog.razor` via injected `IDialogService` (MudBlazor coexistence — Phase 7 migrates dialog content). Result of dialog: parses text through `IRecipeFormatParser`, populates current recipe's fields, surfaces unresolved fields. Existing behavior preserved.

### Task 6: Cooking-mode link-only highlight (ED-08)
Verify (read-only check in `CookingMode.razor` — DO NOT modify here, that's Plan 06-02's territory; just confirm): ingredient highlighting reads `step.IngredientLinks` (the canonical `[name](#id)` link list) exclusively. No substring matching. If Plan 06-02 already shipped this, ED-08 is satisfied transitively. This task is a verification-only.

### Task 7: Keyboard a11y (ED-09)
Verify the chip composer's keyboard semantics:
- Tab/Shift+Tab between chips
- Backspace deletes the prior chip when caret is immediately after it
- Arrow keys move caret normally
- Run an axe-core or manual smoke pass: every interactive element has visible focus, no mouse traps
- JS-interop fallback: if `recipe-chip-composer.js` fails to load, contenteditable falls back to plain text and recipe still saves (with `[name](#id)` rendered visibly)
