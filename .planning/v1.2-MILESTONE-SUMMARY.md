# v1.2 Milestone Summary: UI Redesign

**Three phases (5/6/7), 16 plans, 75 requirements — full visual replatform: MudBlazor deleted, Cb atom system + cookbot-design.css tokens replace it across all 9 surfaces (Home / Cookbooks / Pantry / Grocery / AI Chat / Prompt Builder / Recipe View / Recipe Editor / Cooking Mode / Profile + RecipeMade), with the v1.1 chip-composer scope absorbed into Phase 6's Recipe Editor. dotnet build clean, dotnet test 196/196, repo-wide `Mud[A-Z]` grep zero hits, dependency graph contains zero MudBlazor entries.**

## Headline outcomes

- **MudBlazor 8.15.0 fully removed** from `CookBot.Web.csproj`. `dotnet restore` does not download MudBlazor. `project.assets.json` contains 0 MudBlazor entries. Repo-wide `grep -rn "Mud[A-Z]" src/ tests/` returns ZERO hits.
- **All 9 surfaces + RecipeMade migrated** to the Phase 5 atom system + `cookbot-design.css` tokens. Each surface ships against the Claude Design handoff (`.planning/design-handoff/`) layouts.
- **18 dialog content components migrated** to the `<CbDialog>` slot pattern with `CbDialogService` launches. Last `IDialogService` consumer (TopBar in Plan 07-05) removed. `CbDialogHost` + `CbToastHost` mounted globally on `MainLayout`.
- **v1.1 Phase 3 absorbed:** the chip-composer (EDITOR-01..07) was rebuilt in custom Razor against Phase 5 atoms inside Plan 06-04 instead of being shipped in MudBlazor and immediately rewritten.
- **Accessibility audit signed off** across all 9 surfaces (Plan 07-06). 13 targeted fixes shipped — unified `:focus-visible 2px accent outline`, ARIA roles on atoms (button/dialog/menu/list/progressbar/status/radio/checkbox/switch), aria-label on previously title-only icon-only buttons, WCAG AA contrast verified on warm-cream + cocoa-dark.
- **Build + test baseline preserved** end-to-end. dotnet build: 0 warnings, 0 errors. dotnet test --filter "Category!=RequiresApiKey": 196/196.
- **Existing behaviors preserved verbatim:** dark-mode toggle (cookbot_dark_mode localStorage + body.dark-mode class via JS interop), user-switcher with password prompt (CbDialogService), admin "Manage users" (CbDialogService), session-scoped current user (sessionStorage.cookbot_current_user), AI-off per-user kill switch (UserProfile.AiEnabled gates every AI surface), browser notifications in cooking mode (cooking-timers.js), JS interop in chip composer (recipe-chip-composer.js).
- **Canonical RecipeDocument round-trips preserved** from v1.1. AI Chat canvas binds directly to canonical RecipeDocument from IAiRecipeGenerator (POLISH-01 invariant intact — no extractor revival). Recipe View / Cooking Mode / Recipe Editor all read from canonical store; legacy column projection has been retired.

## Inherited from v1.1 (still load-bearing in v1.2)

These contracts ship in v1.1 Phase 1+2 and are preserved verbatim through v1.2:

- **Canonical `RecipeDocument`** is the single source of truth across YAML wire / JSON export / DB column / AI prompt. v1.2 surfaces all read/write through it; legacy column projection retired.
- **Structured-output AI orchestrator** (`IAiRecipeGenerator`) — Anthropic Claude returns canonical RecipeDocument via token-level constrained decoding with bounded validate→repair→fail. POLISH-01 invariant: no three-tier extractor revival.
- **PromptInjectionGuard** + **SecretRedactor** — XML-tagged user content, sanitized error surfaces.
- **AI-off contract** — `UserProfile.AiEnabled` gates every AI surface (sidebar AI rows + Home Generate + Recipe Editor AI Suggestions + Pantry AI populate/standardize + AI Chat + Prompt Builder routes).
- **Trusted-LAN auth posture** — CookBotSettings.AuthMode reserved for future hardening; per-recipe access via UserCanAccessRecipeAsync.
